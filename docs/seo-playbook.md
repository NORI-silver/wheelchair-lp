# SEOプレイブック（wheelchair.shiokonbu.com）

このサイトのSEO作業をするすべてのAIと人のためのルールです。全体のルールは [AGENTS.md](../AGENTS.md)。

## 1. 狙う検索
- **実際に修理先を探している検索**を優先する。PVだけの語（車いす レンタル／おすすめ／選び方）は当面書かない。
- 優先順位とページの割り当ては [seo/keyword-map.csv](seo/keyword-map.csv)。検索量は推定なので、キーワードプランナーの実数が入りしだい置き換える。
- 最優先は「{市区町村} 車いす 修理／出張修理」。次に症状・製品（パンク、電動、ブレーキ）、困りごと（壊れた、どこで直す）。
- 表記ゆれは「車いす（車椅子）」とタイトルか冒頭で一度併記して両方を拾う。

## 2. ページの種類とURL
| URL | 中身 | 作り方 |
|---|---|---|
| `/guide/{slug}/` | 困りごと・制度のガイド | 手書き（`content/`） |
| `/repair/{症状・製品}/` | 料金相場＋依頼先 | 手書き＋DBの書き出し |
| `/repair/{pref}/` 、`/repair/{pref}/{city}/` | 地域の出張修理業者一覧 | DB（wheelchair-db）の書き出しから自動生成 |
| `/shop/{id}/` | 事業者の詳細 | DBの書き出しから自動生成 |

地域×症状（例 `/repair/chiba/kashiwa/puncture/`）は作らない。地域ページの絞り込みで受け、検索で表示が出た組み合わせだけ後から切り出す。

## 3. 地域ページを index にする条件（薄いページを作らない）
- 市区町村ページ：出張対応が**明記または確認済み**で、個人宅OK、最終確認日が90日以内の業者が**3社以上**（wheelchair-db の `area-summary` の `indexable`）。さらに、そのうち**2社以上がその市区町村を名指し**していること。都道府県全域の業者だけで3社になる市区町村は、どの市も同じ中身になるので都道府県ページで受ける。
- 地域ページは `data/areas.json`（wheelchair-db の `export_pages.py` で書き出す。公開情報だけ）から `tools/areas.py` で生成する。手で書かない。
- 満たさないページは `noindex` にして、都道府県ページへリンクする。
- 地名だけ差し替えた本文にしない。その市への出張費、最寄りの拠点、その市の補装具の窓口など、地域ごとに違う情報を必ず入れる。

## 4. 書き方
- 冒頭（`.answer`）で答えを先に書く。料金の目安、最初に連絡する先など。
- 数字（料金・営業時間・地域）は**公式に確認できたものだけ**。出典リンクと確認日を書く。
- 他社の料金を載せるときは、社名・出典URL・確認日を並べ、「依頼前に各社に確認」と添える。法人専門の業者は個人向けの一覧に出さない（載せる場合は明記する）。
- 対応可否・到着時刻・料金は推定であることを明記する（フッターに共通文あり）。
- 制度（介護保険の福祉用具貸与、補装具費、消費税の非課税）は厚労省・自治体・国税庁の一次情報にリンクする。
- 危険な作業（バッテリー・配線の分解など）を勧めない。

## 5. 技術
- ページは `content/` に「先頭にJSONのメタ情報、`---` の行、本文HTML」で書き、`python3 tools/build.py` で `index.html` と `sitemap.xml` を作る。生成物もコミットする（GitHub Pages がそのまま配信する）。
- タイトル28〜35字目安、メインの語を前半に。ディスクリプション80〜120字。
- 構造化データは BreadcrumbList と Article のみ。他社の口コミ・評価の Review マークアップは付けない。
- スマホ幅（390px）で横スクロールが出ないことを確認する。

## 6. 効果測定
- Search Console は wheelchair.shiokonbu.com を独立したプロパティとして登録する（shiokonbu.com の既存SEOツールはこのサイトに使えない）。
- 変更の効果判定は変更から14日以上たってから。
